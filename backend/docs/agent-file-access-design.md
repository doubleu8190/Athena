# Agent 文件访问与执行环境设计

状态：设计稿，尚未实现。具体改动见 [改造方案](agent-file-access-implementation-plan.md)。

## 1. 审批规则与执行环境分开

配置目录是默认工作目录，也可以作为基础文件工具的免审范围。Settings 中的开关只控制是否启用目录内免审，不关闭工具本身；工具是否启用仍由原工具开关决定。审批规则在本地和 Docker 两种环境中相同。

| 操作 | 默认审批规则 |
| --- | --- |
| 已开启免审，list_directory、read_local_file、write_file、edit_file 操作有效配置目录内文件 | 直接执行，不审批 |
| 上述工具操作配置目录外文件 | 展示实际路径和操作，批准后执行 |
| exec_shell | 默认每次审批整条命令，包括脚本和子进程 |
| 免审开关关闭、未配置目录或配置目录不可用 | 所有 Agent 工具操作都需审批，包括 shell 和 read_worker_result |

沿用现有工具审批设置：基础文件工具默认 false，shell 默认 true；用户可以主动调整设置，但不能跳过“关闭或未配置时全部审批”以及“目录外文件操作审批”。风险等级只作提示，不让基础工具因 medium/high 自动进入审批。

没有可用默认目录时，文件操作必须提供绝对路径，shell 必须明确工作目录；不自动使用后端代码目录。参数不足先说明缺少的信息，再发起审批。

审批不绕过操作系统权限、工具启用状态、任务白名单和文件类型限制。单次批准不增加永久免审目录；参数或实际访问范围变化后重新审批。

## 2. 可选执行环境

- **本地模式**：基础文件工具直接调用共用文件操作模块，只有 shell 启动子进程，不依赖 Docker。
- **Docker 模式**：启用 Docker 沙箱后，所有 Agent 工具都在容器中执行，包括 read_worker_result 和旧别名；Docker、镜像或挂载不可用时返回错误，禁止自动改用本地执行。

Athena 是否用 Docker 部署，与工具是否使用 Docker 沙箱是两回事。实施时将 SANDBOX_ENABLED 默认值改为 false，SANDBOX_REQUIRED 仍默认 false；未显式配置时使用本地模式，不覆盖用户已设置的值。任一为 true 就使用 Docker，两者都为 false 才使用本地模式，不新增另一套选择来源。只关闭 EXEC_SHELL_ENABLED 不影响基础文件工具。

本地 shell 使用服务账户的系统权限，审批针对整条命令，不能逐项拦截脚本内部的文件访问，也不保证停止主动脱离进程组的后台程序。需要强制隔离脚本和子进程时，应选择 Docker。两种模式审批一致，不代表隔离能力一致。

## 3. Docker 隔离和目录外授权

有可用默认目录时挂载到 /workspace；未配置时不挂载隐含的宿主机目录，由本次审批明确目标或 shell 工作目录。容器根文件系统只读，工具程序放在工作区之外，使用固定解释器和入口接收 JSON，不加载工作区的同名模块或配置。禁止提权、特权容器、Docker socket 和后端凭据，默认禁网。

目录外操作的批准必须能在容器中落实，不能只弹审批却没有访问方式：

- 读取文件或列目录：审批后只读挂载目标，映射到本次操作的 /approved/target。
- 新建、覆盖或编辑文件：为支持临时文件和原子替换，需要临时读写挂载目标父目录。审批页面明确展示这个实际范围；未批准父目录范围就不执行。
- Docker shell 需要额外文件时，通过 additional_paths 明确申请，与整条命令一起审批；不靠解析命令文本猜测挂载。每项为 name、path、access，例如 {"name":"input","path":"/data/input.csv","access":"read"}，固定映射到 /approved/input。name 唯一、只含字母数字和下划线、不以数字开头、最多 32 字符；access 为 read 或 write，write 表示读写。源必须存在，新建文件应申请父目录。

Docker 命令直接使用这些固定容器路径，后端不改写已批准命令。审批展示宿主机路径、容器路径及权限；模型可提交别名，但不能任意指定挂载位置。本地命令使用实际宿主机路径，不接受非空 additional_paths，不创建 /approved 路径。工具说明中标明当前环境及路径规则。

附加挂载只对本次操作有效，由后端生成，不能挂载宿主机根目录、Docker socket，或开放后端配置及执行代码等自保位置。没有获准的路径不暴露给容器；审批不能让 Agent 自行提供 Docker 参数。后端与 Docker 服务无法确认路径对应关系时返回部署配置错误。

Docker 每次调用使用临时容器；本地与 Docker 共享文件操作模块、权限判断和结果格式，不强求使用同一种进程调用方式。设置、审批、系统存储仍由后端负责，不能变成接受任意路径的工具后门。

## 4. 路径和链接处理

相对路径以配置目录为起点，绝对路径用于明确请求目录内或目录外对象。拒绝 .. 路径段、NUL、URI 等无效输入，不展开 ~、环境变量和通配符。审批前仅检查路径及元数据，不读取目录外正文或枚举目录。

普通文件操作只检查实际访问路径，不递归扫描整个工作区：

- 列目录只返回直接子项；符号链接显示为不可访问，不跟随目标。路径中经过符号链接时报错，不因其他位置存在链接而禁用整个目录。
- 拒绝当前目标为多硬链接文件、设备、FIFO、socket 等特殊对象；使用目录句柄逐级打开，防止检查后通过链接替换路径。
- Docker 挂载不递归带入子挂载，也不接收外部挂载变化；本地模式遇到暂不支持的挂载边界，拒绝当前路径。

**大目录处理建议，待确认：** 将“修改 cwd”和“缩小挂载”分开。增加可选 workspace_path，只把本次需要的子目录挂到 /workspace；cwd 只改变该挂载内的工作位置。移除“超过 10,000 项就不支持”的固定门槛，硬链接检查流式进行，只保留可配置的检查时限。检查未完成时不得跳过防护，可由 Agent 提出更小的 workspace_path，或由用户调整检查时限后重新调用；挂载范围变化重新审批。不做全树缓存、文件监听或自动隐藏依赖目录，普通文件工具仍只检查目标路径。

## 5. Settings 和文件工具

新增文件访问卡片，开关标注“允许配置目录内免审批”，默认关闭。关闭不禁用工具，所有操作改为审批。目录可留空或清空，此时同样全部审批；配置非空目录时必须真实存在且可访问，不自动创建，拒绝根目录及与服务自保位置重叠的免审范围。保存后生效、重启后保留；失败不改变原配置。

状态只显示目录状态、沙箱状态和 shell 开关。未配置目录表示全部审批，不是工具不可用；沙箱未启用是本地模式，也不是工具故障。已选 Docker 但不可用才阻止执行。目录、免审开关或执行环境改变后，旧任务和旧审批不能静默改用新配置。

| 工具 | 第一版限制 |
| --- | --- |
| list_directory | 不递归，每页最多 200 条，扫描上限 10,000 项，默认不显示隐藏文件 |
| read_local_file | UTF-8 普通文本，单文件最多 1 MiB，每次最多 200 行、64 KiB，返回 sha256 和截断标志 |
| write_file | create 不覆盖；replace 要求 expected_sha256；最终文件最多 1 MiB，父目录必须存在 |
| edit_file | 提供 expected_sha256，old_text 非空且只匹配一处，随后使用统一写入函数 |

保留 BOM、换行和普通权限，拒绝特殊执行权限或无法安全保留必要元数据的文件，不提供 append。写入在锁内比较 hash，通过同目录临时文件原子提交；冲突返回 file_changed，不覆盖当前文件。此保证只适用于基础文件工具；shell 失败或取消可能留下部分修改，不自动回滚。文件锁不阻止外部编辑器在最后检查与提交之间修改文件。

## 6. 限制和恢复

沿用现有 60 秒执行超时、1,000,000 字节输出上限；Docker 默认 1 CPU、512 MiB 内存、128 个进程，建议临时目录限 64 MiB。输出在采集时截断，读取先检查大小，不先加载任意大内容。

本地模式只保证工具自身的输入、输出和超时限制，不承诺与 Docker 相同的 CPU、内存或进程隔离。第一版不提供整个工作目录的磁盘配额；/tmp 限制和基础工具的 1 MiB 上限不等于 shell 总写入量限制。

本地文件工具直接调用模块，不创建子进程、不为每次读取登记 PID；取消时等待正在进行的读写结束后再释放锁，协程超时不代表系统 I/O 已停止。后端进程退出后不存在独立文件运行器遗留，有副作用的未知结果仍由现有账本报告，不能自动重写。

Docker 和本地 shell 保留运行器恢复：确认容器或登记的进程组停止后，终结原记录并释放锁，允许新任务。读取未完成记为失败；写入或 shell 结果不确定记为 outcome_unknown，不自动重跑。无法确认运行器停止时才暂停工具及配置切换，并保留管理查询和重新检查入口。详细步骤见改造方案。

第一版针对 Linux/macOS 普通本地文件系统；Windows、网络文件系统和未验证的挂载方式暂不开放。主机管理员属于可信方，不处理恶意本机进程修改文件系统或任意内核漏洞攻击。
