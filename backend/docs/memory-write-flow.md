# 当前记忆写入流程

本文描述 2026-10-28 精简后的实现。此前设计文档中的逐候选回执、第二次 LLM 决策和自动派生 procedure 已被本流程替代。

## 输入与调度

Run 完成、失败或取消时，在终态事务内调用同一入队函数，按 Run ID 创建唯一记忆作业。会话的项目不可变，领取作业时从会话读取项目。`CompletedTurn.project_id` 为必需字段。Worker 使用租约中心领取、续租和提交终态。

首次领取时冻结有限的任务状态和工具来源，供 episode 使用。事实提取的首次结果另存冻结清单，空清单也表示已经提取完成。重试不重新生成候选。快照写入与项目遗忘共用来源锁，已遗忘轮次不能被迟到的模型响应恢复。

## 事实路径

1. 对有正文、非命令且长度符合限制的输入调用结构化提取模型。模型只分析本次对话，不读取全库记忆。
2. 模型必须输出事实键、值、类别、范围、极性和陈述意图。程序使用会话项目构造实际范围 ID；只有明确个人偏好或身份可进入全局范围。
3. 对每条候选生成与顺序无关的稳定 ID。已存在该 ID 的记录直接跳过，包括已替代或已删除记录。
4. 仓储按结构化范围、主体和事实键查询有效事实组。规则解析器决定创建、修订、忽略或跳过，没有第二次 LLM 调用。
5. 在事务外生成 embedding，再在一个事务中检查租约、遗忘标记及事实组版本，提交事实、修订关系和 embedding。

相同值和极性忽略；集合的新成员可以共存；明确更正或撤回只处理唯一目标；普通单值矛盾保留新旧值及关系；未知属性或多目标歧义跳过。撤回必须明确指向原文中出现的值。

不持久化逐候选决策和投影状态。已提交记录通过稳定 ID 保证重放幂等；没有写入的忽略或跳过候选，在整轮重试时允许按最新事实重新判断。embedding 失败会使该候选失败并触发作业重试，不会单独留下无向量的新事实。

管理属性以数据库列为准，JSON 保存结构化事实和扩展内容；响应中的管理元数据从列重建。

## 任务回顾路径

有执行证据时，模型提出任务回顾；程序校验来源 ID，并依据冻结任务状态确定 outcome。回顾按轮次唯一保存，直接保存 project_id，不再使用项目绑定表。

事实与回顾分别执行：事实不满足触发条件或处理失败，不会阻止回顾分支。已保存回顾在重试时复用。可复用经验保存在回顾的 reusable_learnings 中，使用 episode 检索，不自动复制成 procedure。当前证据不提供确定的测试范围，摘要契约和 UI 已移除 verification_scope。

## 数据与验证边界

保留项目隔离、来源引用、事实组并发复核、稳定 ID、租约检查和来源遗忘标记。用户删除事实、回顾或项目后，后台重试不得恢复相同来源内容。

开发阶段直接清理旧数据并重建受影响的表，不提供旧记录适配、回填或旧类名别名。PostgreSQL 集成测试使用独立临时 schema，验证并发冲突、事务回滚、向量共同提交和项目遗忘；模型抽取质量仍需真实模型验收，结构和并发测试不能代替该验收。
