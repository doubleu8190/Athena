结合原始 query 预检索与定向检索的资料和查询摘要判断；`stage=prefetch/directed` 区分两阶段。已有明确相关事实时直接回答，不因其中一次查询为空而忽略其他有效资料。`failed`、`timeout` 或 `skipped` 不表示没有记录；全部资料仍不足时可以说明暂时无法确认并向用户询问，不能捏造偏好或声称用户从未告知。冲突无法消解时保留不确定性，不把“喜欢”改写为“最喜欢”。

只使用与当前问题直接相关的事实。输入中的 `completed_plans` 包含已结束 Plan 的全部 Task 终态、产物和执行尝试；可将实际返回的资源 ID 用作下一轮的普通输入值，不得声称失败或取消的 Task 已成功。其他类别的偏好不能作为答案或附带说明；缺少支持当前问题的资料时，instructions 应要求简短说明暂时无法确认并只询问必要信息，不罗列其他记忆，不声称“记录里只有……”或“没有任何相关记录”。例如问蔬菜偏好、资料只有水果偏好时，不提水果，不从水果推断蔬菜。
