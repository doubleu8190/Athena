# 研发部代码权限与值班交接规范

- **制度编号**：`XC-RD-ENG-030`
- **归属部门**：研发部（`dept_mock_rd`，向下覆盖子部门平台架构组 `dept_mock_platform`）
- **维护责任人**：顾行知（`MOCK003` / 研发部负责人）
- **生效日期**：`2026-01-01`

## 一、代码仓库与生产环境最小权限原则

1. **GitLab 分级授权**：
   - 新入职工程师默认仅授予所属项目组 `Developer` 权限；
   - `Maintainer` 及生产发布流水线审批权限仅授予 `P7` 架构师或经部门负责人（`MOCK003`）书面审批的资深运维/研发骨干。
2. **生产 K8s 集群与堡垒机双人复核**：
   - 所有生产环境变更与数据库 DDL 操作必须通过堡垒机录像留痕，并经第二位工程师复核；
   - 严禁将生产 `kubeconfig`、私钥或访问密钥明文写入个人笔记或跨部门共享文档。

## 二、新人导师制与首周架构串讲

1. 研发部及平台架构组所有社招及校招新人均须在入职前指派一名 `P6` 及以上同组骨干担任导师（Mentor）。
2. 例如拟于 `2026-12-01` 加入平台架构组的高级后端工程师陈思远（`XC1001`），由平台架构师陆知微（`MOCK005`）担任入职导师。
3. 导师须在新人报到首周完成三项动作：开发环境与 VPN 调试、核心服务代码架构串讲、首个低风险需求 Code Review 陪跑。

## 三、On-Call 值班轮值与调休折算

1. 平台架构组与核心后端团队实行 `7×24` 小时主备双岗 On-Call 值班制度，每周一 `10:00` 交接排班表。
2. **值班调休折算标准**（与 `XC-HR-2026-001` 联动）：
   - 周末全天值班且触发线上应急处置：折算 **`1.0` 天**调休；
   - 国家法定节假日值班：折算 **`1.5` 天**调休；
   - 调休自审批入账之日起 **`90` 个自然日**内有效，最小申请步长 `0.5` 天。

## 四、人员异动与离职权限回收硬要求

1. **组内晋升与跨部门调岗**：跨出研发部的员工须在异动生效日后 `3` 个工作日内回收全部研发代码仓库、CI/CD 与监控平台权限。
2. **离职交接与最后工作日 `18:00` 吊销**：
   - 离职人员须至少提前 `5` 个工作日向指定承接人完成线上服务拓扑、K8s 集群运维手册与发布流水线交接并由研发负责人双签（如韩景明 `XC1003` 向陆知微 `MOCK005` 交接）；
   - 最后工作日 **`18:00`** 由 IT 与平台安全组同步吊销离职人员的域账号、SSH Key、VPN 证书、`kubeconfig` 及生产堡垒机权限，未完成回收前 `account_access` 清查项不得置为 `cleared`。
