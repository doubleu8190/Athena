## 此前问题及追加修复

1. P1：文件上传及替换先写唯一原件，再检查幂等/数据库配额。重放、冲突或配额
   拒绝可生成无 source 记录的孤儿，不计入用户持久化配额，至少保留 24 小时。
   反复请求可耗尽共享磁盘。请求体单次限制不能限制累计占用。
   需加入上传准入/配额预留、重放提前复用，并区分确定未提交与提交结果不确定，
   在不破坏后者原件安全的前提下回收确定无引用对象。
2. P2：文本及文件替换的请求摘要含服务端当前 document.title。替换后改名再以
   原键/原内容重放会错误冲突。摘要应只包含稳定目标和客户端实际请求参数。

上述问题已由上传预留（先查重放、原子计费、稳定 key、fenced 回收）、有界暂存准入
以及仅包含客户端参数和稳定目标的替换摘要修复。引用键以单条 UNION ALL SQL
读取，避免预留登记时孤儿扫描漏看。复审结论 PASS；新增快照交错集成验证待结果。

此前审查位置：app/knowledge/service.py 上传约229/329行、替换摘要约258/306行；
adapter/knowledge/repository.py 配额约64行。行号可能随后续修改变化。
