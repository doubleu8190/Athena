## 1. 已确认范围

- 文档原件仅存放 MinIO，移除本地原件存储支持，不提供存储类型开关。
- PostgreSQL 继续保存元数据、版本、解析文本、分块、全文索引、向量和任务状态；手动输入文本沿用数据库存储。
- 客户端通过 Athena API 上传、下载，沿用归属和权限校验；Worker 直接读取 MinIO。私有桶不公开访问，不新增客户端直传或预签名下载。
- 所有知识库共用部署级私有桶；连接地址、凭据、桶名和 TLS 由环境变量配置，不新增管理员配置页面。
- 本地仍允许上传暂存、解析临时文件、OCR 及模型缓存。
- 不迁移测试原件。切换时清空文档及关联处理数据，保留知识库和项目关联配置。
- 原件写入成功后才登记待解析文档及任务；上传失败允许重试。删除原件由后台负责，失败自动重试；后台清理孤儿对象。

## 3. 实施建议：存储与配置

以下细节属于待整体确认的实施方案。

在 `adapter/knowledge/storage.py` 新增显式实现 `OriginalStore` 的 `MinioOriginalStore`，符合 domain 定义端口、app 编排、adapter 提供实现的分层。删除原 `LocalOriginalStore` 及导出。不为了本次改造重排其他已有知识库模块。

复用对象键 `<owner哈希>/<source_id>/<hash前两位>/<sha256>`，不使用客户端文件名作为对象路径，不暴露凭据或内部地址。桶专用于本部署的知识库原件；其他环境使用不同桶，避免孤儿扫描影响其他部署。

建议配置：

| 环境变量 | 规则 |
| --- | --- |
| `ATHENA_KNOWLEDGE_MINIO_ENDPOINT` | 必填，主机及可选端口，不含桶路径。 |
| `ATHENA_KNOWLEDGE_MINIO_ACCESS_KEY` | 必填，使用该桶的服务凭据。 |
| `ATHENA_KNOWLEDGE_MINIO_SECRET_KEY` | 必填，不记录到日志。 |
| `ATHENA_KNOWLEDGE_MINIO_BUCKET` | 必填，API 和所有相关 Worker 一致。 |
| `ATHENA_KNOWLEDGE_MINIO_SECURE` | TLS 开关，默认 true，沿用严格布尔解析。 |

移除 `ATHENA_KNOWLEDGE_STORAGE_ROOT`，保留本地暂存空间检查和 OCR 缓存配置。知识库关闭时不要求 MinIO 配置，也不主动连接。启用时校验配置与桶可访问性，错误须可定位；禁止静默回退本地。

桶由部署方预先建立并设为私有，应用不自动创建桶或修改桶策略。首期不启用桶版本控制或对象保留锁，确保删除后的物理清理符合预期。API/Worker 凭据须支持上传、读取、删除、列举对象和必要的桶检查。

使用 MinIO Python SDK；实施前核对官方 SDK 与部署版本，锁定可兼容的依赖版本。同步 SDK 调用不得阻塞事件循环：使用有界线程执行、有限网络超时与有限请求重试；读取响应必须释放连接。API、知识库 Worker、Run Worker 复用同一配置构建逻辑，进程退出正确释放资源。SDK API、精确超时默认值和条件写能力须在实施前验证，不在本文声称已验证。

## 4. 数据与失败流程

### 上传及重试

1. API 鉴权、格式校验、大小限制和配额预留沿用现有逻辑。
2. `put` 校验对象键及实际 SHA-256，保存完整原件后才返回成功；保留相同 key、相同内容重放的幂等语义，不接受内容冲突。不得依赖多段上传的 ETag 等同 SHA-256。
3. 成功后由现有数据库事务创建来源、文档/版本、幂等结果和 ingestion 任务。Worker 不处理尚未成功登记的上传。
4. 写入超时可能实际已成功：保留预留，由重试确认对象内容。数据库提交结果不明确时不得立即删除原件，避免删除已提交文档的来源。
5. 未提交对象通过现有预留过期机制和孤儿清理最终回收；不新建跨存储事务或补偿任务系统。

现有同 key 写入不会合法对应不同内容：键由服务端来源 ID 与内容哈希生成。实现仍须验证已存在对象的真实内容，不能仅凭对象自报元数据认定一致；具体写入机制需经真实 MinIO 并发测试确认。

### 下载及解析

先按 owner、知识库、文档及版本验证可见来源，再读取 MinIO；未授权请求不能触发对象读取。下载保留文件名、安全响应头及现有响应格式。对象确实缺失与临时网络错误要区分，不把断网解释成不存在。

Worker 保留现有解析隔离、临时文件及发布 fencing。网络超时和服务端暂时故障可重试；原件缺失、权限错误等须记录明确错误码，不无限重试 ingestion。沿用现有任务重试上限和手动重试入口。

### 删除、清理与一致性

删除文档的数据库事务软删除并登记 cleanup；API 不同步删除对象，不因 MinIO 暂不可用而撤销已成功的逻辑删除。移除 service 中遗留的同步删对象循环，保留现有仓储端口兼容形状，避免无关改造。

后台复用 cleanup 租约、fencing、引用检查和退避。已不存在的对象视为删除成功；部分删除后失败可以重跑。只有对象清理完成且租约有效才完成数据库清理。权限等配置故障保留待清理任务并可观察，修复配置后可继续。

孤儿扫描仅列举专用桶中的合法知识库键，分页处理；只删除超过既有 24 小时宽限期、且没有来源或上传预留引用的对象。使用对象修改时间，不使用本地文件 mtime。删除前再次核对引用，保留现有预留 fencing；不能把扫描失败或数据库查询失败当作空引用集合。应验证“扫描快照后上传/提交”竞争，不误删有效对象。中断上传产生的未完成分段对象也要有清理手段；优先利用部署桶的未完成分段上传过期规则，实施时按 SDK 实际上传机制确认是否需要。

存储适配器将 SDK 异常转换成稳定的领域存储异常；API 将暂时不可用映射为 503 且不泄露底层信息，Worker 据异常类型安排重试。更新过期预留清理的异常处理，单个对象失败不阻断后续清理项。错误日志记录操作和可定位标识，不记录密钥或原文。

## 5. 测试数据清理与切换

提供显式执行、仅面向此次测试环境的清理脚本；不放进应用启动或普遍生效的 Alembic 迁移。实施和清理执行分开汇报，不能仅因脚本已写好就声称已切换。

1. 停止 API 写入、知识库 Worker 及可能访问知识库的 Run Worker，等待在途任务退出。
2. 核对目标数据库；在事务中清除 `knowledge_jobs`、`knowledge_requests`、`knowledge_chunks`、`knowledge_document_versions`、`knowledge_documents`、`knowledge_sources`，按实际外键顺序执行（`knowledge_upload_reservations` 与 `knowledge_upload_slots` 已于迁移 `20261210_0043` 移除）。
3. 保留 `knowledge_bases`、`project_knowledge_bases`，以及用户、项目、会话和其他领域数据。事务提交后核对保留配置及文档计数。
4. 确认本地原件目录只用于已清除的测试数据，再清理该目录；不得误删 OCR、模型缓存或其他数据。不导入旧对象。
5. 配置已创建的私有桶，部署 MinIO 存储实现，启动各进程并执行上传、解析、下载、删除冒烟验收。

数据库结构预计无需变更。若实施核对发现额外外键或知识库关联数据，须补齐清理范围，禁止使用不受控的 `CASCADE` 清理其他领域。

## 6. 实施顺序与验证

1. 增加 MinIO 适配器、存储异常、统一配置和必要依赖；改造所有组装位置及生命周期，移除本地原件实现。
2. 保留上传预留、幂等和配额机制，接入存储异常；删除仅走后台；适配现有 cleanup 和孤儿扫描。
3. 将依赖本地路径及 mtime 的测试改为领域假存储与真实 MinIO 集成测试。假存储仅用于测试，不提供生产本地存储选项。
4. 增加测试数据清理脚本及使用说明，更新 `.env.example`、README 和旧知识库设计/实施方案中的存储约定。
5. 按项目规定由 Implementer 实施并测试，Terra Reviewer 独立审查实际 diff；有问题由 Implementer 修复并重新审查，最多三轮，最后由 Root 验收。

验收必须覆盖：

- 真实 MinIO + PostgreSQL 上完成上传、解析、检索、版本下载、删除及物理回收；保留中文 OCR 现有行为。
- 上传超限/格式错误不登记任务；配额及相同幂等键重放行为不变；并发相同请求仅产生一个有效来源。
- 上传失败、写入超时后实际成功、数据库提交失败/结果不明确均可恢复，不误删有效对象。
- 越权下载不会读取对象；桶匿名访问被拒绝；原件不存在与网络中断的响应和任务状态符合上述规则。
- MinIO 暂不可用时逻辑删除仍成功；cleanup 失败后重试；部分成功删除、租约丢失、共享引用受保护。
- 孤儿分页扫描只删除过期无引用对象，保留新对象、来源引用和预留引用；数据库/列举失败不误删；多 Worker 和并发上传不误删。
- 清理脚本在隔离数据库演练：文档相关数据归零，知识库及项目关联完整，上传槽位可重新使用，其他领域数据不变。
- 知识库关闭可在无 MinIO 配置时启动；启用且缺配置不静默降级；API/各 Worker 指向同一桶。针对变更运行 Ruff、mypy 和相关单元/集成测试。

真实 MinIO 集成测试不可用时须明确报告未验证项，不能用假存储测试替代验收。
