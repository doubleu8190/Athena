# LLM 模块实施方案

状态：待用户确认；本文是对 `llm-design.md` 的项目落地提案，不代表代码已经实现。设计文档中已确认的供应商与协议选择继续有效，整体方案及本文具体选择需确认后实施。

## 1. 当前项目与目标

- Python 3.12 项目依赖集中在根目录 `pyproject.toml`；已有 `jsonschema`、Pydantic（由 FastAPI 依赖引入），尚未声明 OpenAI SDK。现有项目无依赖锁文件。
- `backend/src/main.py` 的 `create_app` 从环境读取配置、组装服务，lifespan 负责释放数据库；现有测试也直接注入服务或创建无数据库的应用。
- `domain/tool` 已有不包含远端来源的 `PublicToolDefinition`，`ToolManager.list_public_tools` 可读取该投影。其 `tool_id` 用于应用侧关联，发送模型的字段仍只能是名称、描述和 Schema。Run 尚未接入本模块。
- `domain/message/model/part.py` 有文本、工具调用、结果及文件引用；LLM 使用独立类型，由未来 Run 转换。`FileRefPart` 不直接发送。
- `common/json.py` 当前为空；若需要共用 JSON 功能，先在此实现小型公共函数，避免另建重复工具。无需使用日期时不引入日期处理。

目标是使内部调用方可独立使用单次非流式、流式、结构化调用，并符合设计文档的隔离、校验和资源清理要求。不新增 API、数据库、工具执行或 Run。

## 2. 拟修改位置

| 位置 | 职责 |
| --- | --- |
| `backend/src/domain/llm/model/`、`ports.py` | 与 SDK 无关的请求、消息、工具、结果、续接项、事件、错误和调用端口；适配器显式继承端口 |
| `backend/src/app/llm/` | Profile 选择、能力及请求校验、工具快照、结构化结果校验和对外服务 |
| `backend/src/adapter/llm/` | Responses 请求与响应转换、异步 SDK、流事件重组、上游异常安全映射；必要的协议模型及 converter 放在该目录 |
| `backend/src/main.py` | 可选组装服务，注入 `app.state.llm_service`，在 lifespan 关闭自建客户端；保持无 LLM 配置时现有应用和健康检查可用 |
| `pyproject.toml` | 固定经过接口验证的 OpenAI SDK 版本；直接声明业务使用的 Pydantic 版本范围；保留现有 `jsonschema` |
| `.env.example`、`README.md` | 配置样例、启动和联调说明，不包含实际凭据 |
| `backend/tests/test_llm_*.py` | 领域及服务、协议转换、流和生命周期测试；真实服务测试单独标记并默认不运行 |

目录内按职责拆文件，不预先创建无用途 repository、HTTP 路由或与 SDK 类型等价的冗余包装。

## 3. 接口与数据边界

- 对外保留 `complete`、返回异步上下文管理器的 `stream`、`generate_structured` 三个接口，每次至多发起一次上游调用。结构化请求禁止 tools。
- 领域消息显式表达 system/user/assistant/tool，输出按顺序表达文本和工具调用，工具结果以 `call_id` 关联。响应保留状态、未完成原因、模型、上游响应 ID、请求 ID、可缺失的 usage。空输出合法，但不能把拒答、未完成或异常响应当成普通成功。
- 续接项使用领域内专用、可序列化的不透明数据类型封装 Responses 所需内容，包括 reasoning 等；只由 adapter 校验和解释。显式上下文、`store=false`；不使用 `previous_response_id` 依赖托管状态。Run 将来负责持久化，首版验证响应项及工具结果重放后顺序和 `call_id` 不丢失。
- 工具输入在请求边界做深拷贝并冻结或等价隔离，包括嵌套 Schema；先验证唯一名称、有效 JSON Schema、tool choice 与绑定关系。每次响应按当次快照验证工具名称、JSON 对象和 Schema，保留多个调用的顺序及 ID。通过 `jsonschema` 本地校验；使用明确的 Schema 方言，拒绝不能安全本地解析的外部引用，避免隐式网络读取。
- 结构化调用先生成并预检 Schema 的已知受限规则，不改写业务语义；上游成功后分别检查拒答、完成状态、JSON 和 Pydantic 验证。预检不能保证兼容服务接受 Schema，上游拒绝仍转换为明确错误。

## 4. 配置与生命周期提案

- 增加可选 `ATHENA_LLM_PROFILES`，值为部署方管理的 JSON 对象，键是 Profile 名称，值包含 `base_url`（可省略使用 SDK 默认地址）、`api_key_env`（环境变量名而非密钥）、`model`、能力声明、超时、并发及内容大小上限。模型不硬编码；空配置表示不启用 LLM。解析应拒绝未知字段、重复 Profile、非法值和缺失凭据，错误不回显配置或密钥。具体样例在实施时写入 `.env.example` / README。
- 能力明确列出 tools、stream、structured 和支持的生成参数。请求要求未声明能力则调用前失败；可选参数仅在受支持时发送。请求可设置更严格的超时/大小限制，不得突破部署上限；明确区分请求的输出 token 上限和本地字节、工具数量上限。
- 按实际连接配置及凭据身份复用客户端；不同凭据不共用。并发配额按 Profile 独立限制，等待、调用和流消费均在受控时限内；流持有配额至关闭。明确错误与取消路径都释放配额，不在日志或对象展示中泄露秘密。
- `create_app` 支持注入已有 LLM 服务，注入对象由调用方管理；自行创建的客户端由应用管理。组装失败时关闭已创建资源；lifespan 正常或异常退出关闭客户端与数据库，某项关闭失败不阻止其他资源释放。LLM 服务即使没有数据库也可独立组装。
- 限制及默认值在代码和文档中统一定义并验证；数值属于实施提案，需在编码前定稿，不依赖请求方自行限流。SDK 的 `max_retries=0`，应用层也不重试。

## 5. 协议、流与错误

- 调用前构造 Responses 原生输入、非严格 function tools 和可选生成参数。非流式与流式共用终态解析、工具参数校验及续接转换，确保完整结果语义一致。
- 流直接异步迭代，不引入无界队列。以 output/content 索引及上游标识重组交错调用和分片，限制文本、参数及工具数量。只在参数完整并校验后发 `ToolCallCompleted`，仅在上游正常完成且终态校验通过后发一次 `ResponseCompleted`。拒答、截断、错误事件、断连和缺失终态均不可产生成功终态。
- 异步上下文管理器在正常完成、异常、调用方提前退出和取消时关闭上游流并释放配额；取消继续传播。确定 SDK 版本后以其真实流关闭接口和模拟 transport 验证，不假定 SDK 事件一定完整或按单调用顺序到达。
- 领域错误区分配置、能力、认证、限流、超时、连接、上游、协议、工具参数、结构化输出、拒答和未完成；清理错误不掩盖原始取消。日志只记录安全元数据和固定错误码，不记录上下文、参数、原始错误体或密钥，也不向外传播含敏感信息的上游异常文本。

## 6. 执行顺序与验证

1. 锁定并验证 SDK 接口和传输依赖；定义领域契约、配置和错误，补充项目依赖。
2. 完成非流式转换、校验与结构化输出，再接入流重组及资源限制；接入应用组装和关闭。
3. 用模拟 transport 和固定协议样本覆盖成功、空输出、多工具及交错分片、工具校验、结构化 Schema/拒答/截断、未知事件及异常响应、上下文重放。并发测试覆盖不同工具和凭据隔离、等待取消和限额释放；生命周期测试覆盖提前退出、异常、取消、组装/关闭失败。断言不重试及敏感信息不出现在错误和日志。
4. 执行相关测试及全量 `.venv/bin/python -m pytest`、`ruff check .`、`ruff format --check .`、`mypy`。独立 Reviewer 审查实际 diff；有效问题按项目要求修复并复审，最多三轮。
5. 有部署方提供的模型、地址和凭据时，单独运行真实服务联调，核对普通、流式、tools、结构化和续接能力；分别记录结果，不能用模拟测试代替。未提供时标记联调未完成，凭据不进入仓库或日志。

## 7. 实施前需确认

- 已确认：使用单个 JSON 环境变量承载命名 Profile；注入服务由调用方管理，自行创建的客户端由应用管理。
- 实际部署限制的默认值、确切 SDK 固定版本将在确认方案后依据 SDK 接口及测试确定；如对配置大小、流超时或默认容量有明确运维要求，应在实施前提供。模型名、base URL 和凭据可以等到真实联调前提供。

配置与生命周期约定已确认；整体实施方案仍待确认，确认前不开始代码实施。真实联调凭据不是编写和模拟测试的前置条件，但缺少时不能宣称真实兼容性已验证。
