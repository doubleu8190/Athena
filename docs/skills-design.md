# Skills 功能设计

日期：2026-11-12。状态：产品规则已确认；本文已同步进程、对象回收和 Office 校验的
精简决策，对应代码已实施，仍需独立 Reviewer 与 Root 最终验收。

## 1. 目标与已确认规则

Skill 是可复用的业务处理方法，可以携带操作指南、Python 脚本、模板及参考附件。它指导 Agent 如何完成某类任务，不自行授予工具权限，也不能绕过现有审批。

以下规则已在设计讨论中逐项确认：

1. 管理员统一导入、维护和启停技能包；普通用户使用已启用的技能，不上传或维护私人技能。
2. 支持 Agent 自动选择和用户手动指定。先提供名称和简介，选中后加载完整指南，按需读取模板及附件。
3. 管理员上传 ZIP，根入口为 `SKILL.md`；可选目录为 `scripts/`、`templates/`、`references/`。更新上传完整新版本，保留历史版本，管理员查看指南和文件清单后启用。
4. Run 创建时固定当时已启用的技能目录和版本。更新、停用只影响新 Run；澄清、审批恢复等原 Run 延续原版本。
5. 首期执行管理员安装的可信 Python 脚本。不要求独立容器或隔离服务，不强制禁止联网、访问宿主文件和凭据或修改技能包文件，不设置脚本 CPU、内存、进程、磁盘、时间及执行次数限额。Agent 调用已有工具 / MCP 仍遵守其权限及审批。
6. 管理员按技能配置脚本执行审批，默认关闭。开启后每次实际执行均需审批；外部工具独立遵守自身审批策略。
7. 输入由 Agent 明确选择：用户提供的文件、同会话已有产物和当前技能包资源。以原件副本作为输入，修改生成新输出；缺少文件时明确报错并请求补充。
8. 输出归属当前会话，可下载、可被后续任务引用；脚本明确指定交付文件，临时文件不自动交付。
9. 平台统一提供 Python 依赖，技能声明需求，导入时检查；缺少依赖阻止启用，运行时不下载或安装。
10. 同一 Run 可组合多个技能，由 Agent 协调顺序、传递产物；首期不增加技能互相自动调用机制。要求冲突时说明，必要时澄清。
11. 允许调整参数后再次执行，禁止 Agent 修改技能包脚本或编写临时 Python。每次执行目录独立，失败文件不自动交付，已有成功产物保留。
12. 普通用户看到技能名称及版本、执行状态、审批用途和输入文件、结果文件及明确失败原因。代码、原始日志及内部路径属于管理员排查信息。

本轮修订以用户最新决定替代此前的强制隔离、脚本访问限制和执行次数上限。管理员负责审核安装的可信代码。新增的会话存储配额不恢复上述脚本运行限额。平台文件授权与不可变版本约束的是平台接口及持久化记录，不是对脚本的沙箱限制。禁止 Agent 修改或临时编写脚本的调用规则仍保留。

系统提示词负责全局行为，Skill 负责某类业务方法，工具负责实际操作，知识库提供参考资料。Skill 内容不能覆盖后端鉴权、执行边界和预算检查。

## 3. 技能包协议建议

本节描述当前实现约束；字段和格式变更仍按本设计的兼容边界处理。

```text
sales-report.zip
├── SKILL.md
├── scripts/
│   └── build_report.py
├── templates/
│   └── report.xlsx
└── references/
    └── metrics.md
```

建议 `SKILL.md` 使用 YAML 元数据加 Markdown 正文。元数据声明稳定标识 `slug`、名称、简介、所需依赖，以及可执行脚本的路径、用途和 JSON 参数结构。正文描述业务步骤、资源使用方式和交付要求。平台生成不可变版本 ID；包内版本文字不能作为唯一身份。

脚本必须显式登记，入口位于 `scripts/` 下且为 `.py` 文件。辅助 Python 模块可以随包携带，但不能被 Agent 临时添加。执行采用固定入口程序和结构化参数，不接收 shell 命令、`python -c`、任意解释器选项、启动文件路径或任意环境变量。技能声明不能扩大平台能力。

依赖声明使用包名及受支持版本约束；平台与统一 Python 环境的依赖清单比对，拒绝 URL、Git、本地路径等安装来源。导入时检查，启用及执行前复核，不满足时明确报错。首期不要求不可变镜像，记录实际 Python 与依赖版本便于排查；Run 固定技能内容，不保证平台升级后运行环境完全不变。

依赖字符串须符合 PEP 508，统一使用 `packaging.requirements.Requirement` 解析；`InvalidRequirement`、直接 URL 来源及平台不支持的声明在导入时返回 422。使用实际脚本解释器环境的 `importlib.metadata.distributions()` 获取发行包名称/版本，按规范化发行包名与 `Requirement.specifier` 比对，不能用 Python import 模块名代替包名。API 与 Worker 环境不一致时，以目标执行环境为准；未取得环境检查结果不能宣称依赖满足。

marker 在实际执行环境求值，为 False 则该要求不适用。首期拒绝 extras 声明并返回 422，不以“基础包已安装”误判可选依赖满足；后续如支持 extras，需要验证对应 Requires-Dist 闭包。格式合法但缺包或版本不符允许保存版本，检查状态为 `dependency_unsatisfied`，禁止启用；环境变化后重新检查而不修改不可变包内容。导入检查结果是带环境信息的记录，不是永久满足证明。

参考：[Packaging Requirement](https://packaging.pypa.io/en/stable/requirements.html)、[Python importlib.metadata](https://docs.python.org/3/library/importlib.metadata.html)。

导入时校验：

- ZIP 结构、单一根入口、UTF-8 文本和元数据格式；新建技能的 slug 唯一，更新必须显式指定已有技能且标识匹配。
- 拒绝绝对路径、`..`、符号链接、硬链接、设备项、重复或规范化后冲突路径及加密压缩包。
- 同时限制压缩体积、累计解压体积、文件数、单文件大小和压缩比，在解压过程中计数，不仅信任 ZIP 元数据。
- 脚本登记、参数结构及资源引用必须指向包内合法路径。依赖不满足时可以保存为不可启用版本，展示具体原因。
- 不因文件后缀而信任内容；前端指南按安全 Markdown 渲染，附件下载不作为可执行 HTML 展示。

建议起始参数：ZIP 25 MiB、解压总量 100 MiB、500 个文件、单文件 25 MiB，指南正文 100,000 字符。参数属于实施建议，最终应与上传、对象存储及上下文预算统一校验。

## 4. 管理与用户流程

### 4.1 管理员

新增“技能”管理页：列表、详情、导入、版本历史、当前版本切换、启停及脚本审批配置。上传完成先展示指南、文件清单和校验结果；首次导入不自动启用。上传新版本也不自动替换正在提供的版本，由管理员明确切换。

可将“切换版本并启用”合为一次提交。保存审批配置、启停、版本切换使用配置修订号进行并发检查；冲突不覆盖另一位管理员的修改。技能包版本不可修改，首期不提供版本删除及在线编辑脚本。选择旧版本作为当前版本复用同一不可变内容，不重写历史。

管理员能查看包内容和受权限控制的执行日志；普通用户目录仅返回已启用技能的名称、简介等使用信息，不开放管理接口和整包下载。用户使用的任务仍可能让模型读取部分指南或资源，不能承诺技能内容对用户绝对保密。

### 4.2 普通用户

1. 正常提交任务，或在输入框选择一个或多个技能。
2. 提交时服务端验证所选技能仍启用，在同一 Run 创建事务中固定完整可用技能目录及选中项；若选择已失效，返回明确冲突，保留输入，不静默忽略。
3. 用户指定技能的指南在首次推理前加载；自动选择通过模型调用技能加载工具完成。
4. Agent 需要文件处理时，选择脚本、结构化参数及输入文件。启用审批则展示已冻结的本次执行请求。
5. 执行后显示成功/失败及文件；后续任务可通过会话文件 ID 引用产物。

新会话上传建议先创建实际会话，再上传并提交 Run；不额外引入匿名临时附件系统。只有文字任务仍沿用现有创建流程。用户指定技能表示按其方法处理，不保证脚本一定执行；缺少所需工具或数据时应说明并澄清。

### 4.3 会话文件存储规则

单文件上传上限建议为 50 MiB，边接收边计数，不能只信任 Content-Length；会话内已发布文件总数上限建议为 100，用户上传与脚本产物共同计入。原子发布时锁定所属会话或专用配额行校验总数，批量产物超额则整组不发布，并发上传/产物发布不得突破上限；未发布对象不计数，失败或取消产生的孤立对象在停写维护窗口离线回收。失败或取消不占用已发布名额。首期没有单文件删除入口，到达上限返回明确错误，由用户使用新会话继续。

这是本轮新增的会话存储配额，不是脚本临时磁盘、CPU、运行内存或执行次数限制，也不限制脚本生成但未交付的文件。50 MiB 只约束用户上传，不自动施加于生成产物；首期未承诺每用户/全站总容量或速率防刷，100 个文件也不等于全站磁盘配额。

用户上传及产物发布统一使用可配置类型白名单，首期建议文本 txt/csv/json/md/log、xlsx/docx/pptx、pdf 和 png/jpg/jpeg/webp；按扩展名、内容特征和 MIME 交叉校验，不仅相信客户端 MIME。拒绝 exe/sh/app、脚本及其他可执行/主动内容，不接受目录或压缩包绕过文件类型规则。技能 ZIP 导入仍走独立管理员入口，不受会话白名单替代。

所有会话文件下载使用 `Content-Disposition: attachment`（正确编码安全文件名）、`X-Content-Type-Options: nosniff` 和合适 MIME，不内联渲染未可信 HTML/SVG；有访问权限才可下载，不返回永久公开地址。

## 5. 数据归属与分层建议

沿用 PostgreSQL、私有 MinIO、现有 Run Worker 与审批体系；新增 Python 子进程执行适配器。

建议最小数据结构：

| 数据 | 作用 |
| --- | --- |
| `skills` | 稳定身份、slug、当前版本指针、启用状态、脚本审批开关、配置修订号。 |
| `skill_versions` | 不可变元数据、指南、文件清单、对象键及内容摘要、依赖检查结果、依赖需求、创建人和时间。 |
| Run 的有类型技能快照 | 创建时可用版本清单、名称/简介、审批策略及用户选中项；引用不可变版本，不重复保存整个 ZIP。 |
| `session_files` | 文件 ID、会话/所有者、来源（上传或产物）、安全文件名、MIME、大小、对象键、摘要、创建时间及来源调用 ID。 |
| 脚本执行记录 | 与现有工具调用一对一，保存执行环境、技能版本、脚本路径、冻结输入和参数摘要、执行状态、错误及管理员日志引用。仅保存现有调用表未覆盖的信息。 |

快照、包清单、参数和结果 JSON 使用显式 Pydantic 类型与序列化边界，不能任由无结构字典贯穿层间。Run 快照的空目录和未初始化状态必须可区分，不得在恢复时补读最新目录。

建议模块职责：

- `domain/skill`：包、版本、快照、脚本请求/结果、仓储及脚本执行端口。
- `app/skill`：导入校验、管理用例、加载资源、组织执行；不依赖 ORM 或进程管理实现。
- `adapter/skill/model`、`repository`、`converter`：按领域组织持久化，显式实现领域接口。
- `domain/file`、`app/file`、`adapter/file`：会话文件元数据、授权、上传/下载和产物发布。文件不是知识库文档，不触发解析、嵌入或索引。
- 脚本执行 adapter：实现领域端口，负责启动、终止、日志与产物收集；仅组合根选择具体实现。
- `api/skill.py`、`api/files.py` 及对应 DTO/converter：管理和用户 HTTP 边界，复用认证与写请求来源校验。
- 现有 Run repository 在创建事务中绑定技能快照；工具 runtime 通过显式端口调用上述用例。
- 前端 admin 增加管理页，chat 增加技能选择、上传/下载、执行进展与审批摘要。

以上新增路径是设计建议，尚未创建模块。

## 6. 版本、事务和并发

### 6.1 配置与 Run 创建

管理员发布以数据库当前指针切换提交为生效点。完整可用目录用一条一致快照查询读取，再作为同一创建事务的 Run 字段持久化。Run 创建和管理员更新并发时，绑定该次读取可见的版本；更新成功后才提交的新任务应读取新版。

submit/retry 先走既有幂等重放，再读取目录；重放返回原 Run，不重新选版本。用户重试失败任务创建新 Run，使用当前目录，并重新验证原先显式选择的技能；停用时明确报错，不能重新引入旧版。answer、审批恢复及 Worker 恢复不重绑。

技能审批策略建议随技能目录一起固定。管理员修改只影响新 Run；外部工具仍沿用自身现有语义。用户身份和会话/文件访问权限在执行及交付时实时复核，版本固定不等于固定用户访问权。

并发启停、切换及配置保存采用修订号校验和必要行锁，数据库原子提交，失败不改变当前配置。不改变现有 Session / Run 锁顺序，不把对象存储或脚本调用放在数据库事务里。

### 6.2 对象存储与数据库

先将 ZIP、资源、上传或产物写入不可变私有对象，再在数据库事务发布元数据引用。上传完整性和摘要不匹配则不发布。事务失败允许形成不可见孤立对象；API、Worker 和管理写路径不执行在线对象回收，孤立对象只由停写窗口中的离线维护命令在宽限期后、并确认 `session_files`、`skill_versions` 和 `skill_executions.log_object_key` 均无引用时删除。不能先发布 DB 成功再异步补文件。

版本和被 Run 引用的包不能删除。会话文件随会话可见性鉴权；会话删除后立即不可下载或被新执行读取，物理对象在后续离线维护时回收。禁止因引用 ID 可猜测而跨会话读取。

### 6.3 执行与产物提交

复用工具调用 ID、审批批次和执行准入。脚本实际启动前持久化调用与执行记录；相同调用只准入一次。审批绑定技能版本、脚本、参数和输入文件内容标识，审批后不得替换，修改需创建新调用。

成功产物先落私有存储，再在有效 Run 租约和实时权限检查下，同一数据库事务发布文件记录、执行结果和文件引用。只有提交成功的产物可见。失租、取消胜出或权限失效时不发布，残余对象清理。

同一调用的已提交结果幂等返回，不重新执行。进程失联导致执行效果不确定时，沿用当前 UNKNOWN/Run 失败边界，不静默重放；用户重试属于新 Run。正常确定的脚本报错可让 Agent 调整参数发起新调用，但不能将一次审批复用于多次执行。

### 6.4 多文件结果协议

现有 `ToolResultPart.artifact_id` 只能表示单个引用，不能承载一项脚本调用的多文件交付。当前 `_tool_result_draft` 只写 `outcome.canonical_output()`，`_execution_to_llm` 也仅采用 `output` 或单个 `artifact_id`；在工具结果之外附加多个 `FileRefPart` 不足以解决问题，因为此模型转换路径不会读取它们。

建议为 `ToolResultPart` 增加有类型的 `artifacts` 集合，每个元素为 `ArtifactFileRef`：`file_id`、`filename`、`mime_type`、`size_bytes`。这些字段由成功发布的 `session_files` 记录生成，不信任脚本自行提供的文件 ID 或元数据；按输出清单顺序排列，拒绝重复引用。无文件时为空集合。

例如一次调用得到：

```json
{
  "type": "tool_result",
  "tool_call_id": "call_report",
  "status": "success",
  "output": "已生成销售报表和趋势图。",
  "artifacts": [
    {"file_id": "file_report", "filename": "report.xlsx", "mime_type": "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet", "size_bytes": 20480},
    {"file_id": "file_trend", "filename": "trend.png", "mime_type": "image/png", "size_bytes": 8192}
  ]
}
```

示例 `output` 仅展示用户可读含义；实际持久化仍保留现有 `ToolOutcome.canonical_output()` 信封。文件集合是独立的结构化字段，不依赖 `outcome.data` 文本、文件名分隔符或 JSON 字符串内解析。既有 `artifact_id` 如继续服务于其他工具的大型结果引用，保留其原语义；技能的交付文件统一使用 `artifacts`，不同时向两处写同一交付引用，不为旧字段新建迁移兼容框架。

服务端仅在脚本成功且全部声明文件校验、对象存储写入完成后，才生成文件 ID。发布事务同时写入所有 `session_files`、完整 `artifacts` 结果消息和调用完成状态，保持第 6.3 节的原子性；任一失败则整组不发布，失败结果的 `artifacts` 为空。发布重放返回原文件 ID 和原顺序。

具体变更范围：

- `domain/message/model/part.py` 增加引用类型和集合，`app/message/service.py` 验证字段、唯一性及成功结果约束；用户发送的普通文件引用继续用 `FileRefPart`。
- `adapter/message/converter/message.py` 完整序列化/反序列化集合，`api/dto/message.py` 与 `api/converter/message.py` 返回同一结构，前端 chat 类型同步。
- 扩展工具执行结果与完成命令的数据传递，`RunExecutor._tool_result_draft` 接收已发布的有类型产物引用，不从模型输出解析文件。仓储发布接口须使引用消息与文件元数据在同一事务形成，不能先提交成功结果再单独补文件。
- `app/run/context.py` 的 TOOL 转换显式将所有文件的 ID、名称和类型加入模型可见结果，即使 `output` 非空也不能跳过集合；保持一个工具调用对应一个 TOOL 结果，不为每个文件生成重复的 tool response。
- `ToolOutcome` 截断只处理文本数据，不截断或丢失结构化文件集合。完整模型结果计入预算；预算不足时保留持久化全集，通过会话文件列表分段发现，不默默只保留首个文件，也不恢复已移除的脚本输出数量限额。
- `app/run/compression.py` 保留产物来源及可发现的文件引用，文件服务是权威来源，后续 Run 可重新列举会话文件，不依赖摘要保留所有文件名。
- `ChatMessageList.tsx`、`RunExecutionTrace.tsx` 和调用详情用户态 DTO 使用同一安全文件集合，逐项提供下载入口；不得直接展示对象键或宿主路径。多个界面可以展示同一文件，但不在会话存储中重复创建文件记录。

`SafeSkillApprovalProjection.input_files` 表示执行前的输入，结果的 `artifacts` 表示执行后交付；不得用输入文件列表替代输出集合。用户下载、模型后续引用仍必须通过会话文件授权，持有引用不等于永久访问权。

## 7. 渐进加载与模型接入

建议新增固定数量的内置工具，而不是每个 Skill 动态注册一个工具：

- `skill_load(skill_id)`：只能加载当前 Run 快照里的版本，返回指南、资源和脚本清单，；以成功调用的持久化记录作为加载证据，不另设权威加载表。
- `skill_read_resource(skill_id, path, ...)`：按包清单读取文本资源，限制大小并支持分段；二进制资源返回文件信息供脚本使用，不伪装为文本。
- `skill_execute(skill_id, script_path, parameters, input_file_ids)`：登记入口、参数和输入文件，生成明确执行用途，按技能策略进入审批。
- `session_file_list(after_file_id: str | None = None, limit: int = 50)`：按稳定创建顺序分页返回当前会话文件的 ID、安全文件名、大小、MIME 及后续游标；limit 为 1–100。会话身份从可信执行上下文取得，不接收模型指定的会话 ID。
- `session_file_read(file_id: str, offset: int = 0, limit_bytes: int = 65536)`：仅读取当前会话 UTF-8 文本文件，返回内容、起止字节位置、`next_offset`、`eof` 和截断信息。offset 为非负字节偏移，limit_bytes 为 1–65536；遇 UTF-8 字符边界须明确报非法偏移，尾部只返回完整字符并据实际消费字节推进游标，不能拆字符或将解码错误替换为乱码。支持 txt/csv/json/md/log 等明确文本类型，实际字节必须可严格解码；xlsx/png/pdf 等二进制返回 `file_not_text` 和已授权元数据，提示使用技能脚本，不读取为文本。两工具均执行实时会话授权，读取前检查文件归属，不需要脚本审批。

### 7.1 动态审批与批次提交

实际代码接入点为 `RunExecutor._submit_and_execute_batch`（`backend/src/app/run/executor.py`），不是 `RunWorker`。目前 `_validate_business_call` 返回本地错误或 `None`，之后仅凭 `definition.requires_approval` 构建 `BeginToolCallBatchItem`；现状不能直接支持按技能审批，必须显式修改这一判定链路。

采用以下规则：

1. 内置 `builtin_skill_execute` 的 `RuntimeToolDefinition.requires_approval` 固定为 `False`，不以全局开关阻塞所有技能。识别该调用应使用服务端冻结定义的 builtin 来源及稳定 `tool_id`，不能只匹配模型传入的工具名称。
2. 批次提交前，先执行现有工具与参数校验，再基于当前 `_ExecutionState.run` 的有类型技能快照校验 `skill_id`、固定版本、已登记脚本路径及脚本参数结构。所需版本元数据应在执行准备阶段按固定版本解析，不能让同步本地校验器临时访问数据库或读取最新配置。现有 `validate_call(definition, model_name, arguments)` 没有 Run 上下文，实施时需显式传入技能校验上下文或增加独立的纯校验方法，不能假定原签名已经具备此能力。
3. 任一校验失败，生成 `immediate_outcome` 及对应错误结果，`requires_approval=False`，不进入待审批状态，也不启动脚本。快照不存在、类型非法、目标不在快照内或无法解析固定策略时均不得默认为免审批后继续执行。
4. 仅校验通过的 `skill_execute` 调用，从 Run 快照中该技能的固定审批配置计算本次 `requires_approval`；不得使用管理员最新配置，不读取模型提供的审批布尔值。
5. 其他工具仍使用 `definition.requires_approval`。将计算后的单次判定写入 `BeginToolCallBatchItem`，交给既有 `begin_tool_call_batch` 原子持久化消息、即时结果、审批记录和 Run 状态。无需修改通用工具定义为动态属性。
6. 审批恢复复用已经持久化的调用参数、目标版本和 `requires_approval`，不重新读取配置作审批判定。执行前仍复核参数与实时文件/会话权限，但不得替换已批准请求。

判定顺序如下（仅为设计伪代码）：

```text
outcome = validate_tool_and_arguments(definition, call)
if outcome is None and is_builtin_skill_execute(definition):
    outcome, skill = validate_against_run_skill_snapshot(run, call)

if outcome is not None:
    requires_approval = False
elif is_builtin_skill_execute(definition):
    requires_approval = skill.requires_approval
else:
    requires_approval = definition.requires_approval
```

加载和读取本身不触发脚本审批。同一批次如果包含其他合法的待审批调用，整个批次仍按现有屏障等待所有审批决定；非法调用已经记录即时失败，不出现在待审批列表，不应把“非法调用不进入审批”误解为“整批不等待其他合法调用”。

### 7.2 活跃指南与上下文预算

主提示词、Run 固定的可用技能简要目录和活跃技能完整指南共同构成不可压缩的系统基准上下文，在 `context.py` 中按此顺序动态构建 SYSTEM 消息，位于摘要和会话历史之前；技能指南不能覆盖平台协议。它们不是追加的会话消息，不进入历史压缩输入，也不把压缩摘要视为活跃指南来源。

每次实际推理、压缩前估算、压缩后重建及失败回退均复用同一基础上下文构建函数，计入工具 schema、消息封装和既有重试上下文。先扣除基础 Token 与预留输出，剩余窗口才是历史可用预算；摘要和近期历史的额度基于该预算。当前 `compression.py` 已有 base_tokens/input_budget 计算，但触发阈值仍按整个 context window 计算，接入时必须同时调整估算与触发判定：历史用量与历史预算乘 trigger_ratio 比较，避免大指南反复触发无效压缩。完整请求仍做最终窗口校验，基础上下文本身放不下时明确报错，不靠压缩指南解决。

活跃技能集合不另设表或易失缓存作为权威来源。每轮及 Worker 恢复时，读取 Run 创建时的用户显式选中项，再扫描该 Run 已持久化且成功完成的 `skill_load` 调用及其冻结参数，取 skill_id 去重并按 Run 固定目录顺序排列。识别依据为服务端 builtin 工具身份、调用完成状态及成功结果，不解析模型文本或仅凭工具名称；失败、拒绝、仅提交未完成的加载均不生效。合法但尚未完成的加载仍按现有工具恢复语义处理，不推定成功。

查询加载证据必须覆盖当前 Run 的全部持久化执行记录，不受摘要 cutoff、历史分页窗口或当前模型上下文裁剪影响。历史消息压缩不删除这些记录；成功加载与工具完成在同一事务提交，避免结果可见而加载证据缺失。缓存只能作为可重建优化。取到 skill_id 后只解析 Run 固定版本，不能查最新目录补绑；快照缺失或加载记录损坏时明确失败。

名称、简介和稳定 ID 常驻简要目录，完整指南仅对显式选中和成功加载的技能注入。资源文本仍是按需工具结果，不自动提升为系统指南；全部资源读取和文件读取也计入请求预算。

## 8. Python 脚本执行建议

首期由 Run Worker 通过领域端口，在平台统一 Python 环境启动子进程，不要求独立容器或隔离服务，不新增脚本资源、超时和执行次数限额。沿用现有 Run 生命周期、模型请求预算及取消机制。

每次执行创建独立工作目录，将固定版本的技能文件及明确选中的输入复制进去。目录用于组织输入输出，不构成安全隔离。脚本按运行进程的操作系统权限联网、读取宿主文件与环境凭据，也可修改技能文件副本；平台不将这些修改回写不可变版本，新调用重新从固定版本准备文件。

Agent 仍只能请求登记脚本及结构化参数，不能生成临时 Python 或提交任意命令。平台统一预装依赖，不提供执行时安装步骤；这属于平台调用协议，不保证阻止可信脚本自行使用系统能力。

### 8.1 文件式 IPC 协议

统一使用 UTF-8 JSON 文件传递输入，不把参数正文放进命令行或环境变量。平台在本次工作目录写入 `input.json`，关闭文件后再启动入口脚本；通过平台生成的 `ATHENA_INPUT_PATH` 环境变量传递其绝对路径，不同时维护另一套命令行输入协议。该变量只携带路径，不携带 JSON 或凭据。工作目录及输入文件仅对执行账号开放；这不构成沙箱，也不能防止同账号的可信代码访问。

输入结构如下：

```json
{
  "parameters": {"month": "2026-10"},
  "input_files": {"file_sales": "/work/call_123/inputs/sales.csv"},
  "output_dir": "/work/call_123/outputs"
}
```

`parameters` 来自已冻结并校验的请求，文件映射来自平台授权后复制的输入，输出目录由平台创建；模型不能覆盖路径。技能包资源位于执行目录的技能副本中，入口及工作目录约定由平台 SDK/示例明确。

脚本退出码为 0 后，必须在 `output_dir/manifest.json` 写入以下结构；无交付文件也必须写 `{"outputs": []}`：

```json
{
  "outputs": [
    {"path": "report.xlsx", "label": "月度销售报表"},
    {"path": "trend.png", "label": "销售趋势图"}
  ]
}
```

路径相对于输出目录，不接受绝对路径、越界路径、重复路径或链接，文件必须存在且为普通文件；`label` 为纯文本展示标签，不替代真实文件名，不参与路径解析。若展示标签随产物持久化，应作为第 6.4 节 `ArtifactFileRef` 和文件元数据的可选字段同步传递，唯一身份仍是平台文件 ID。`manifest.json` 是控制文件，不作为交付文件。平台只发布清单声明文件，不扫描目录自动交付。

退出非零、清单缺失、JSON/结构错误或任一文件校验失败，均生成明确错误且不发布任何产物。stdout/stderr 不参与结果协议。文件与 JSON 用流式读写及增量解析处理，不将全量输出文件读入 Worker 内存；不因此恢复脚本输出数量或磁盘限额。

### 8.2 进程组、取消与失租

POSIX 环境启动子进程必须设置 `start_new_session=True`，不使用 shell 拼接命令。记录启动时的进程组 ID（新会话首进程的 PID），避免主进程已退出后再调用 `os.getpgid(proc.pid)` 导致查找失败。取消、失租、现有 Run 截止时间到达或 Worker 正常关闭时，对该组发送 `SIGKILL`，处理进程组已不存在的幂等情况，并等待/回收直接子进程，避免僵尸。异步取消期间也必须保护并等待清理流程完成。本地诊断记录只保存 Run、调用、Worker、PID、PGID、时间和工作目录，供人工排查，不是跨重启身份或存活证明。

正常脚本退出后也清理同组残留后代，再校验清单和发布文件，避免后台进程继续改写产物。日志读取任务必须在进程组清理后收敛，不能无限等待后代保留的管道。

进程组信号只能覆盖仍在该组的进程，不等于任意进程树回收；主动 `setsid`/改变进程组的后代不在保证范围，可信技能不得主动脱离。Worker 被 SIGKILL 或宿主崩溃时 `finally` 不会执行，不能宣称仅靠它实现失联后的强制回收；重启时不按诊断中的 PID/PGID 自动推断或杀进程，遗留目录保守保留并交由人工复核。脚本已完成的宿主文件或网络副作用不回滚，结果不确定沿用 UNKNOWN，不静默重跑。

### 8.3 有界日志收集

stdout/stderr 必须并发、分块消费，禁止使用累积完整输出的 `communicate()` 模式。每次执行两路合计最多保留 5 MiB 原始日志，管道读取缓冲同样有界；达到上限后设置持久化 `log_truncated=True`，停止保存新增字节，但继续读取并丢弃，直到进程结束或被清理，避免 PIPE 写满令脚本死锁。

保留日志在临时目录清理前写入私有对象存储，执行记录保存日志引用及截断标记；普通用户接口不返回日志正文。日志上传失败记录独立排查错误，不将已成功发布的业务产物反转为失败，不为补日志重新执行脚本。

5 MiB 是本次补充的日志收集边界，用于防止 Worker 无界内存增长，不是脚本 CPU、运行内存、运行时间或执行次数配额。

### 8.4 临时目录生命周期

使用 `try/finally` 管理本次唯一工作目录。成功时完成文件校验、产物和保留日志上传、数据库发布后立即删除；失败、取消、失租及发布回滚也必须先清理进程组和日志消费任务，再在 `finally` 删除目录，包括 `input.json`、输入副本、技能副本和输出文件。不为管理员排查保留整个临时目录，排查信息使用独立持久化日志。

清理只能定位平台创建的本次目录，不接受脚本传回的删除路径，不跟随链接递归删除外部内容。清理异常不得掩盖业务结果或取消状态；记录 `cleanup_error_code`，由同一执行路径继续尽力收敛。Worker 启动和周期任务不扫描或自动删除重启遗留目录；崩溃遗留目录需要人工结合宿主工具确认后，在受控窗口处置。不能承诺所有退出路径都立即删除。

| `GET /api/v1/admin/skills`、`GET /api/v1/admin/skills/{id}` | 管理列表和详情。 |

| `POST /api/v1/admin/skills/{id}/versions` | 上传完整更新包；包内 slug 必须与目标技能绑定 slug 完全一致，否则 422。 |
| `GET /api/v1/admin/skills/{id}/versions` | 分页版本历史；详情查看指南及资源清单。 |
| `PATCH /api/v1/admin/skills/{id}` | 带期望修订号提交当前版本、启停和审批配置。 |
| `POST /api/v1/sessions/{id}/files` | 向当前有权访问的会话上传文件。 |
| `GET /api/v1/sessions/{id}/files` | 分页列出可引用的上传文件和产物。 |
| `GET /api/v1/sessions/{id}/files/{file_id}/download` | 实时鉴权后流式下载；不返回永久公开对象地址。 |

现有 Run submit 请求增加显式技能 ID 与输入文件 ID；answer 需要支持等待澄清时补充文件。文件列表及下载不能只检查 owner，必须同时匹配会话与可见状态。手动选择必须参与请求指纹，保持既有幂等冲突语义。

审批和执行状态继续复用现有 Run/工具接口；扩展安全字段用于显示技能名称、固定版本、脚本用途及输入文件名。原始日志增加管理员专用读取边界，普通用户调用工具详情也不能绕过前端限制读取。

### 9.1 用户态审批投影

新增有类型的 `SafeSkillApprovalProjection`，由服务端组装，供待审批项和技能调用详情共同使用；前端不得从裸 `arguments` 拼装技能审批摘要。当前 `ToolApprovalPanel.tsx` 展开后直接显示 `details.data.arguments`，`RunExecutionTrace.tsx` 也有原始参数展示，二者针对技能调用均需切换为安全投影。

建议投影字段及来源：

| 字段 | 服务端来源与规则 |
| --- | --- |
| `call_id` | 已持久化工具调用 ID，作为审批提交身份。 |
| `skill_id`、`skill_name`、`skill_version_id`、`skill_version_label` | 用已持久化调用中的 `skill_id` 解析 Run 固定技能快照及不可变版本；名称不取模型参数或当前管理目录，版本 ID 为权威身份，标签仅供展示。 |
| `script_label`、`purpose` | 固定技能版本登记的脚本名称/用途与服务端格式化摘要；不返回绝对路径或依赖模型解释作为身份信息。 |
| `input_files` | 每项含文件 ID、安全文件名及必要的大小/MIME；根据持久化 `input_file_ids`，在调用所属会话和所有者范围关联 `session_files`，不能跨会话查询后仅在前端隐藏。 |
| `parameter_summary` | 服务端按登记参数结构生成有类型、可读的参数项；只投影可展示字段，隐藏凭据和内部路径，不能将完整参数字典换个字段名返回。若隐去影响授权判断的字段，应明确标识存在未展示参数。 |

`purpose` 表示登记用途，不承诺可信脚本没有其他宿主或网络副作用。文件名作为纯文本展示，去除路径部分及控制字符，不当作 HTML；不得返回对象存储键、服务器路径、环境变量、脚本代码或原始日志。

调用通过校验时构建展示所需的业务快照（固定技能身份、脚本标签、参数摘要及输入文件身份/安全名称），与调用请求在同一次批次提交事务内持久化。该快照绑定第 6.3 节的同一批准对象，避免刷新、管理员重命名、技能更新或恢复审批时展示漂移；不是另存第二份可执行参数。查询时仍实时校验会话与文件权限，失效的文件以不可用标识代替敏感信息，不得改绑另一个文件或退回展示裸参数。必需元数据缺失时返回明确不可审批状态，不允许用户在不完整摘要下批准；拒绝操作仍可用。

具体接入：扩展 `domain/tool/model/execution.py` 中待审批及调用详情的业务投影，`api/dto/run.py` 定义响应 DTO，`api/converter/run.py` 仅序列化已完成授权和关联的投影，不在 converter 内查数据库。`app/run` 查询用例及对应 repository 负责关联冻结调用、Run 技能快照和受权限限制的文件信息，批量查询避免逐项请求。现有 Run 详情中的 `pending_approvals` 直接携带投影，工具详情接口返回同一结构；SSE 只通知变更，刷新走同一查询路径。

技能调用的普通用户详情不返回原始参数，现有 DTO 的必填 `arguments` 需调整为技能专用判别分支或显式空值，不能仅靠前端折叠；原始 `output` / `outcome.data` 也需白名单投影，防止内部日志从其他字段泄漏。非技能工具沿用现有契约。管理员原始排查信息使用独立鉴权接口。审批提交仍只传调用 ID、决策和幂等标识，不接受客户端回传投影覆盖批准对象。

### 9.2 错误与恢复

建议错误语义：包/参数不合法 422，目录或配置并发冲突 409，不存在/不可见按项目现有授权约定处理，执行基础设施不可用返回明确工具错误。用户输入与上传前的编辑状态在冲突和网络失败后保留。导入网络结果不确定时通过导入请求标识或版本摘要核实，不盲目重复创建。

对话展示加载技能、执行等待审批/运行/成功/失败及结果文件。SSE 只用于及时展示，刷新后必须能从数据库恢复相同记录。脚本失败不一定令整个 Run 失败，由 Agent 在预算内继续或解释；UNKNOWN、失租等仍遵守既有 Run 收敛规则。

## 10. 首期范围与排除项

首期闭环必须包括：ZIP 管理与不可变版本、创建时快照、自动/手动选择、渐进加载、可信 Python 脚本执行、依赖校验、按技能审批、会话文件上传/下载/复用、可恢复进展及管理员排查信息。

不包括：普通用户私有技能、在线脚本编辑、运行时安装依赖、Agent 临时编写代码执行、其他语言、技能相互自动调用、技能市场/Git 同步、批量发布、运行中技能紧急撤销及技能效果评测。通过已有 MCP 执行外部操作仍属于已有能力，不因本设计增加权限。

## 12. 可观察的验收条件

- 管理员成功导入包后能查看指南、资源及依赖检查；首次导入不自动启用，普通用户无管理或上传技能权限。
- 包含路径穿越、链接、重复路径、超量解压、未登记入口、非法依赖来源的包被拒绝；缺少平台依赖时无法启用。
- 两位管理员基于同一修订号切换时只有一位成功；失败不改变当前指针，已引用版本保持可读。
- 创建 Run 后发布新版/停用，旧 Run 包括排队、澄清、审批恢复仍用旧版，新 Run 使用新目录；幂等重放不重新绑定，失败任务重试重新验证当前目录。
- 自动选择可加载相关指南，手动选择首次推理前加载；同一 Run 可先分析后制作报告。未在快照内的技能和资源无法通过猜 ID 读取或执行。
- 长目录或指南超出预算时明确失败或请求减少选择，压缩不能导致指南版本变化或活跃指南静默消失。
- 同一 `skill_execute` 定义静态审批值为 False 时，Run 快照中开启审批的技能仍进入审批，关闭的技能不进入；管理员后续修改不影响原 Run 的判定。其他工具的静态审批语义不变。
- 非法 `skill_id`、缺失快照、未登记脚本或参数结构不合法的调用生成即时失败，不出现在待审批列表，也不启动脚本。非法调用与合法待审批调用混合时，仅后者进入审批，批次仍遵守原审批屏障；刷新和恢复不会重新计算策略或修改请求。
- 开启审批后，未批准脚本不会启动；拒绝后可解释或继续任务；再次执行需新审批，审批后不能替换参数/输入/脚本版本。外部工具仍独立审批。
- 平台以副本提供所选输入，不覆盖存储原件，文件接口拒绝跨会话引用；会话删除及权限撤销后禁止平台继续交付。这些接口校验不限制可信脚本直接访问宿主文件。
- 在平台 Python 环境真实运行登记脚本并记录环境信息；依赖不满足时明确报错。修改执行目录中的副本不回写持久化版本，新调用仍从 Run 固定版本准备文件；取消或失租后不发布新产物。
- 正常失败可调参再次执行，不新增脚本执行次数上限；Agent 调用接口不接受临时 Python、任意命令或依赖安装请求。
- 未声明输出、越界路径、链接和失败执行文件不交付；成功产物可下载且在后续 Run 引用。多文件输出以同一发布事务交付，失租/取消竞争不出现半套可见产物。
- 脚本成功但 DB 提交失败不会重复启动同一调用；已提交结果重放相同文件 ID，无法确认的执行不会静默重跑，孤立对象由下一次停写窗口 dry-run/execute 维护处理。
- 待审批项和技能调用详情返回同一用户态投影，正确展示 Run 固定的名称/版本和同会话安全文件名；技能更新或名称变更后刷新不漂移。前端无需查询管理目录或解析原始参数即可审批。
- 普通用户通过直接 HTTP 请求也无法从技能详情的参数、输出或 outcome 读取原始日志、对象键、宿主路径和凭据；跨会话文件 ID 被拒绝，元数据缺失/访问失效时禁止批准且不降级展示裸参数，仍允许拒绝。
- 单次脚本同时生成 `report.xlsx` 与 `trend.png` 时，数据库、消息 API、工具详情、模型 TOOL 结果和前端均包含两个独立文件引用，用户可分别下载并在下一 Run 引用，不能只显示首个 `artifact_id`。
- 多文件序列化往返不丢失 ID、名称、类型、大小和顺序；非空 output、文本截断及历史压缩不会让文件永久不可发现。任一产物写入/发布失败则整组不可见，重放使用相同文件 ID，不生成多个同 call_id 的 TOOL 结果。
- IPC 使用 `ATHENA_INPUT_PATH` 指向 input.json，进程参数和环境变量不包含 JSON 正文；零文件清单成功，清单缺失/非法或任一文件非法整组失败，未声明文件不交付。
- 实际脚本启动同组子进程后，取消、失租、Run 截止时间到达及正常退出均清理组内残留并回收直接子进程；主进程先退出也可完成组清理，不因管道句柄遗留而挂起。主动脱离组与 Worker 硬崩溃的限制明确记录；诊断 JSON 中的 PID/PGID 不用于跨重启自动杀进程。
- stdout/stderr 同时持续打印超过 5 MiB 时，Worker 缓冲保持有界、`log_truncated=True` 且脚本不因停止读管道而死锁；日志落库/存储失败不触发脚本重跑。
- 成功、失败、取消和 DB 发布失败均执行临时目录清理；清理失败记录稳定错误码，Worker 重启不自动扫描遗留目录，崩溃遗留由人工在确认无活跃写入后处置。
- 指南作为不可压缩基础上下文在摘要前注入；长指南同时影响历史预算和触发阈值，完整请求/回退估算一致。Worker 重启从全部已提交成功加载记录和用户选中项重建相同集合，失败加载和摘要内容不改变集合。
- 文件列表分页无遗漏/重复，跨会话不可读；UTF-8 分段读取不拆字符，非法偏移报错，二进制返回元数据及明确错误，不伪装成文本。
- 超过 50 MiB 的上传被流式拒绝，上传与产物并发仍不超过会话 100 文件；多文件发布超额整组拒绝。伪装类型和可执行文件被拒绝，下载响应强制 attachment/nosniff。
- 非法 PEP 508、URL 和不支持的 extras 返回 422；合法但未满足要求可保存为 dependency_unsatisfied 且不能启用，marker 和版本比较使用真实脚本环境。
- 首发导入重复 slug 返回 409，并发首发由唯一约束兜底；更新包 slug 与目标不匹配返回 422，不创建版本或改变当前指针。
- 用户刷新页面后仍能看到固定技能版本、调用状态及文件；普通用户详情无法读取管理员日志、宿主路径或密钥，管理员可按调用追溯错误。
