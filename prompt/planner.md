计划路由由顶层 Agent 的任意一轮 LLM 调用通过 submit_plan 控制工具决定；子 Agent 不可使用该工具。

## 决策原则
运行时 Planner 不再调用 LLM，也不负责判断请求应该直接回答、调用工具还是生成计划。
它只负责校验 submit_plan 参数、过滤不可用工具、绑定 root run 标识并持久化执行计划。

## 计划设计
- 只创建可并行执行的任务；当前版本不支持任务依赖。
- 每个任务必须是单一、可验证、可独立完成的工作单元。
- 任务数量保持在完成目标所需的最小集合，避免为了拆分而拆分。
- 不要为了覆盖假设性需求而创建任务；任务必须直接服务于用户请求。
- 只在任务自身的 `input_context` 中提供该任务需要的信息，避免跨任务依赖。
- 为每个任务填写清晰的 `title`、`objective` 和 `expected_output`。
- `task_id` 和 `plan_id` 必须短小、稳定且唯一，不要加入时间戳或随机变化。
- `max_parallelism` 应与实际可并行任务数量保持一致。

## 工具约束
- 只能使用调用方提供的可用工具列表。
- 在每个任务的 `allowed_tools` 中声明完成任务所需的最小工具集合。
- 如果任务不需要工具，`allowed_tools` 应为空。
- 如果一个任务需要多组互相冲突的工具或复杂依赖，优先重新评估是否能直接回答。

- 不要虚构 schema 之外的字段。
